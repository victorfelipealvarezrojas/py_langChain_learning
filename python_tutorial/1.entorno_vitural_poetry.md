# Entornos virtuales en Python y `poetry env activate`

## 1. Qué es un entorno virtual

Un entorno virtual (venv) es una **instalación de Python aislada para un proyecto**: un intérprete propio y una carpeta propia de librerías.

### Problema que resuelve

Por defecto, Python busca los paquetes en un único lugar: el `site-packages` del intérprete que se está usando.

- Proyecto A necesita `langchain==0.2`
- Proyecto B necesita `langchain==0.3`

Si ambos usan el mismo Python, la segunda instalación pisa la primera y uno de los dos proyectos se rompe. Además se ensucia el Python del sistema.

### Cómo lo resuelve

Cada proyecto tiene su propia carpeta con:

- `bin/python`: enlace al intérprete que, ejecutado desde ahí, busca librerías solo en esa carpeta.
- `lib/pythonX.Y/site-packages/`: las dependencias de ese proyecto y nada más.

### Equivalente en Java

| Java (Maven)                  | Python (Poetry)                  |
|-------------------------------|----------------------------------|
| `pom.xml`                     | `pyproject.toml`                 |
| Classpath armado por proyecto | Entorno virtual del proyecto     |
| Jars resueltos para el build  | Paquetes en `site-packages/` del venv |

Python no tiene un classpath por proyecto. El entorno virtual cumple ese papel.

---

## 2. Dónde lo guarda Poetry

`poetry install` crea el venv (si no existe) e instala ahí las dependencias del `pyproject.toml`. En macOS lo ubica en:

```
~/Library/Caches/pypoetry/virtualenvs/<nombre-proyecto>-<hash>-py<versión>/
├── bin/
│   ├── python        ← intérprete del proyecto
│   ├── pip
│   └── activate      ← script de activación
└── lib/python3.13/site-packages/   ← dependencias del proyecto
```

Ejemplo real (proyecto `visor-doc`):

```
/Users/victoralvarezrojas/Library/Caches/pypoetry/virtualenvs/document-ai-m_Htgv9S-py3.13/
```

---

## 3. Qué significa "activar"

Activar es ejecutar el script `bin/activate` en la terminal actual. **Solo cambia variables de esa sesión**:

- Antepone `.../bin` del venv al `PATH`.
- Define la variable `VIRTUAL_ENV` con la ruta del venv.
- Agrega un prefijo al prompt, por ejemplo `(document-ai-py3.13)`.

Con eso, `python` y `pip` apuntan a los del venv y quedan visibles las dependencias del proyecto. No instala ni mueve nada. El efecto dura mientras la terminal esté abierta o hasta ejecutar `deactivate`.

---

## 4. `poetry env activate`

**No activa el entorno: imprime el comando para activarlo.**

```
$ poetry env activate
source /Users/victoralvarezrojas/Library/Caches/pypoetry/virtualenvs/document-ai-m_Htgv9S-py3.13/bin/activate
```

Un proceso hijo (Poetry) no puede modificar el entorno de la shell que lo lanzó, así que el texto impreso hay que evaluarlo:

| Shell       | Comando                                     |
|-------------|---------------------------------------------|
| bash / zsh  | `eval $(poetry env activate)`               |
| fish        | `eval (poetry env activate)`                |
| PowerShell  | `Invoke-Expression (poetry env activate)`   |

También sirve copiar la línea `source ...` que imprime y ejecutarla.

Desde Poetry 2.0 reemplaza a `poetry shell`, que pasó a ser un plugin aparte (`poetry-plugin-shell`).

---

## 5. Verificación y salida

```
which python                 # antes: Python del sistema o de Homebrew
eval $(poetry env activate)
which python                 # después: .../virtualenvs/document-ai-.../bin/python
deactivate                   # vuelve al estado anterior
```
